## What this is

`kingbot` — a Cloudflare Worker generated by the create-cloudflare CLI. It is still at the scaffold stage: `src/index.ts` returns `Hello World!` and no bindings are configured yet.

`AGENTS.md` holds the Cloudflare-specific guidance (docs links, error codes, product references). Read it before any Workers/KV/R2/D1/Durable Objects/Queues work rather than relying on recalled API knowledge.

## Commands

| Command | Purpose |
|---------|---------|
| `npm run dev` | Local dev server (`wrangler dev`) on http://localhost:8787 |
| `npm test` | Vitest in watch mode; `npx vitest run` for a single pass |
| `npm run deploy` | Deploy to Cloudflare |
| `npm run cf-typegen` | Regenerate `worker-configuration.d.ts` from `wrangler.jsonc` |

Single test file / single case: `npx vitest run test/index.spec.ts -t "responds with Hello World"`.
Typecheck: `npx tsc --noEmit` (src only) and `npx tsc -p test/tsconfig.json --noEmit` (tests). Neither is wired to an npm script.

## Architecture

**Entry point.** `src/index.ts` default-exports an object `satisfies ExportedHandler<Env>`. The `satisfies` (rather than a type annotation) is what gives `request`/`env`/`ctx` their inferred types — keep it when adding handlers such as `scheduled` or `queue`.

**`Env` is ambient, not imported.** It comes from `worker-configuration.d.ts`, a ~580KB generated file listed in the root tsconfig's `types`. Any change to bindings, vars, or compatibility settings in `wrangler.jsonc` must be followed by `npm run cf-typegen`, or `Env` will silently lag behind the config.

**Two tsconfigs, different type universes.** The root config includes only `src/**/*.ts` + `worker-configuration.d.ts` with `types: ["./worker-configuration.d.ts", "node"]` and explicitly excludes `test/`. `test/tsconfig.json` extends it but swaps `types` to `["@cloudflare/vitest-pool-workers/types"]` — that is what makes the `cloudflare:test` module resolve. Code placed outside `src/` and `test/` is typechecked by neither.

**Tests run inside workerd.** `vitest.config.mts` uses `@cloudflare/vitest-pool-workers` pointed at `wrangler.jsonc`, so tests execute in the real runtime with the same compatibility flags and bindings as production. The scaffold demonstrates both supported styles:
- *Unit*: call `worker.fetch(request, env, ctx)` directly with `createExecutionContext()`, then `await waitOnExecutionContext(ctx)` before asserting so `ctx.waitUntil()` promises have settled.
- *Integration*: `SELF.fetch(...)` dispatches through the full Worker pipeline.

Assertions use `toMatchInlineSnapshot`; refresh them with `npx vitest run -u`.

## Configuration notes

- `compatibility_flags: ["nodejs_compat"]` is on, so `node:*` imports are available.
- `observability` and `upload_source_maps` are enabled — logs and stack traces are usable in the Cloudflare dashboard.
- `wrangler.jsonc` ships with commented-out blocks for smart placement, vars, static assets, and service bindings; uncomment in place rather than re-deriving the syntax.
- Formatting is tabs / LF / single quotes / 140 columns (`.prettierrc`, `.editorconfig`). No format or lint script exists; the scaffolded files use double quotes, so match surrounding style in a file rather than reformatting it.
